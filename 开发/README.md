# 开发记录

这里按天记这个项目实际发生过的事：做了什么、方向为什么改、bug 怎么查出来又怎么修好。

一天一个文件，文件名用 `YYYY-MM-DD.md`。同一天有后续就追加在当天文件里，不另开一份。

## 每天写这四段

```markdown
# YYYY-MM-DD

## 任务

今天完成或推进了什么。

## 方向调整

决定改走哪条路，以及为什么。没有就写「无」。

## Bug 与修法

现象、原因、改了哪一处。没有就写「无」。

## 未做

明确放下、下次再做的事。
```

不要把猜测写成已经验证过的结论。修 bug 时写能让下一次直接照着查的原因，不写流水账。
